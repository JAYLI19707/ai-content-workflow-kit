# Migration Checklist

如果你准备把这套资产真正迁进自己的 Codex 内容项目，建议按下面顺序做。第一步，先把你现在已经有的 LaTeX 模板放到固定路径，并明确哪些部分绝对不能改，例如颜色定义、页面框架、box 环境、封面结构。第二步，把根目录的 `AGENTS.md` 改成你的真实项目契约，尤其是输出目录、模板路径、编译命令、命名规则。第三步，只保留最核心的两个提示词开始跑：`00-master-system-prompt.md` 和 `02-episode-generator.md`，不要一开始就把所有流程都叠上去。第四步，建立 `source-log.md` 和 `qa-checklist.md`，让真实性校验和终稿验收先跑通。第五步，再逐渐启用更细的选题器、来源归一器、LaTeX 精修器。第六步，只有当你真的已经连续做了好几期，才考虑把一些人工判断进一步固化进 `.codex/rules/` 或 `starter/` 里的长期规则。

迁移时最容易犯的错有三个。第一个错是把方法论长文直接塞进常驻上下文，结果 Codex 每次都背着一大堆低频信息工作。第二个错是让“找题、讲解、分页、改 LaTeX、核验来源”在一条 prompt 里同时发生，导致输出忽好忽坏。第三个错是没有单独处理真实性，最后虽然内容好看，但来源表述不够稳。你上传的设计文档里反复强调“根契约不是知识库”“低频知识不要常驻”“工作流必须和常驻规则分开”，迁移时最该守住的其实就是这三条。
